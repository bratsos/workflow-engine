`createServerlessHost` accepts `onTick(counts)`, called at the end of every `runMaintenanceTick()` with a copy of the counts it computed (changing it does not change what the method returns), before the method returns them. Combine it with the `engine.stats` command to export gauges. A hook that throws or rejects is caught and logged, and the tick still returns its counts. The hook is awaited for at most the new option `onTickTimeoutMs` (default 5000, the same as `outboxFlushTimeoutMs`, the host's bound on its other optional wait after the maintenance commands finished; a number from 1 to 2147483647, anything else throws a `RangeError` from `createServerlessHost`, and nothing switches the bound off): after that the counts are returned, one warning is logged and the hook keeps running in the background. The bound covers a hook that yields: measured with a hook that never settles and `onTickTimeoutMs: 25`, `runMaintenanceTick()` returned after 28 ms. Synchronous code in the hook cannot be bounded: the timer fires only once it yields, so a body that computed for 60 ms delayed the return by 60 ms.
