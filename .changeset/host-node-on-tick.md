`createNodeHost` accepts `onTick(counts)`, called after every orchestration tick with a copy of the `MaintenanceTickCounts` the tick computed. Combine it with the `engine.stats` command to export gauges. The hook runs outside the tick: ticks never wait for what it awaits, so claiming, polling, lease reaping and the outbox flush do not depend on it. This holds for a hook that yields (awaits I/O or a timer): measured with a hook that never settles, the host ran 16 ticks in 155 ms against 15 without a hook. Synchronous code in the hook runs on the host's thread and no tick runs while it does: a hook that computed for 40 ms on each call at a 10 ms interval left room for five calls in 202 ms. Keep the hook's synchronous part short and await the rest. At most one call is in flight; a tick that finds the previous call still running skips the hook and logs one warning, with how long the call has run, at the first skip, and calls it again once it settles. The warning is not repeated while the hook stays slower than the interval; a call that finishes without any tick skipping it ends the episode. A hook that throws or rejects is caught and logged and never stops the loop. `stop()` waits for a running hook, together with the in-flight tick, for at most `shutdownTimeoutMs`, and no hook starts once it began. A hook must not await `host.stop()`: `stop()` waits for the hook that is waiting for it until `shutdownTimeoutMs` elapses.
