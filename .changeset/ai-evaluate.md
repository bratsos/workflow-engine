Decision models: `ai.evaluate` and `ctx.step.ai.evaluate`.

- **`ai.evaluate(modelKey, { state, questions }, options?)`** answers typed questions about one shared state with a decision model — a model whose output is a typed judgment with probabilities rather than text. TypeSafe's Jev (`typesafe/jev-1.13`, `~typesafe/jev-latest`) is the first, served through OpenRouter's Decisions API. A question is a `choice` (pick one named option; answer carries `choice`, `probabilities` and the provider's `confidence`), a `score` (place the state on an ordered scale; answer carries a fractional `score`, per-level `probabilities`, `confidence` and the echoed `legend`) or a `boolean` (answer carries the `probability` that the statement is true). Each answer is typed from its own question, so a `choice` answer's `choice` is the union of that question's criteria keys, including on an inline object literal. The call goes through the AI SDK's `evaluate` and `openrouter.evaluationModel(id)`, with the same `max_price` routing guard every OpenRouter call carries. It is logged with `callType: "evaluate"`; decision models bill input tokens only, and OpenRouter's reported cost is the recorded cost, the registry's input price the fallback estimate.
- **`ctx.step.ai.evaluate(id, modelKey, spec, options?, stepOptions?)`** is the durable form: the answers are memoised in the step ledger, so a stage that replays after a suspension takes the branch it took the first time instead of asking again.
- **`isEvaluationModel`** on `ModelConfig` marks a decision model; only such a model can answer `evaluate`, and any other throws before a request is made. `workflow-engine-sync` sets it for every catalogue model whose output modality is `decisions` and writes it only on those entries, so a re-sync leaves every other entry unchanged. `listModels({ isEvaluationModel })` filters on it. Re-run the sync to pick up Jev.
- **`registerEvaluationProvider(provider, factory)`** plugs in any other AI SDK evaluation model, as `registerEmbeddingProvider` does for embeddings.
- **Testing:** `MockAIHelper.evaluate` answers every question, and `setEvaluateAnswer(questionId, answer)` (also on `harness.mockAi`) scripts one; unscripted questions get the first `choice` option, level 0 of a `score`, and probability 0.5 for a `boolean`.
- **Breaking for custom `AIHelper` implementations:** the `AIHelper` interface gained `evaluate`, and `AICallType` gained `"evaluate"`. Code that consumes a helper is unaffected; a class that implements the interface itself must add the method.
- **Dependency floors raised:** `ai` to `^7.0.113`, `@openrouter/ai-sdk-provider` to `^3.1.0` (the first with the Decisions transport), `@ai-sdk/provider` to `^4.0.18`. That `@ai-sdk/provider` release replaced its experimental per-model batch types with a provider-level batch seam; the native batch transport now declares the per-model shapes it calls itself instead of importing the removed types. Batch behaviour is unchanged.
