The SQLite adapters refuse a file that another Prisma major wrote. Prisma 6 stores `DateTime` as integer epoch milliseconds in SQLite, Prisma 7 and 8 as ISO text, and SQLite orders every integer before every text value, so across majors every date comparison is decided by the type: a Prisma 7 client on a Prisma 6 file offered a run completed a moment ago to `run.purge` and a run updated a moment ago to `run.reapStuck` (and the reverse never polled a stage whose deadline had passed). `PrismaWorkflowPersistence` and `PrismaJobQueue` on SQLite now compare the oldest and newest stored value of every date column an index leads with (`workflow_runs.createdAt`, `outbox_events.publishedAt` and `dlqAt`, `workflow_stages.nextPollAt`, `job_queue.nextPollAt`) with a `Date` as their client binds it, once per client in one statement of ten index lookups (0.07 to 0.21 ms at 100,000 rows in each of the four tables): the storage class and, when both are text, the form (the text with every digit replaced, which tells Prisma 7's `+00:00` from Prisma 8's `Z`, the path of an upgrade). Every method of both classes throws the new exported `SqliteDateStorageError` (`code: "SQLITE_DATE_STORAGE_MISMATCH"`, `kind` `"class"` or `"form"`, `column`, showing what is stored and what is bound and linking the docs) before it reads or writes anything. Which methods are guarded is decided by name (every method except a short list of synchronous ones, and loading fails if none is wrapped), not by how the code was compiled, so a build that lowers `async` still guards every entry point. The bound class is read off the client, not from a table of majors. An empty database, a schema that is not pushed yet and a file written by the same major are not refused. Checked on real files written by one major and opened by another, in all six directions (6, 7 and 8 against each other). Not detected: a foreign text form on rows strictly between the oldest and newest of a column, and date columns no index leads with; only a file an earlier release mixed can hold them. To move a file to another major, drain it with the major that created it and delete the outbox and idempotency rows (see the Prisma setup guide), then open it with the new one.

New exported `assertSqliteDateStorage(prisma)` runs the same check for code that owns a client (the console read port uses it), and `JobTransport` and `JobQueue` gain an optional `verifyStorage(): Promise<void>` that a host calls at start; the Prisma job queue implements it and `createSpillingJobTransport` forwards it. Nothing is required of a custom transport.
