The SQLite adapters refuse a file that another Prisma major wrote. Prisma 6 stores `DateTime` as integer epoch milliseconds in SQLite, Prisma 7 and 8 as ISO text, and SQLite orders every integer before every text value, so across majors every date comparison is decided by the type: a Prisma 7 client on a Prisma 6 file offered a run completed a moment ago to `run.purge` and a run updated a moment ago to `run.reapStuck` (and the reverse never polled a stage whose deadline had passed). `PrismaWorkflowPersistence` and `PrismaJobQueue` on SQLite now compare the oldest and newest stored `workflow_runs.createdAt` with a `Date` as their client binds it, once per client in one statement answered from the `createdAt` index: the storage class and, when both are text, the form (the text with every digit replaced, which tells Prisma 7's `+00:00` from Prisma 8's `Z`, the path of an upgrade). Every method throws the new exported `SqliteDateStorageError` (`code: "SQLITE_DATE_STORAGE_MISMATCH"`, `kind` `"class"` or `"form"`, showing what is stored and what is bound and linking the docs) before it reads or writes anything. The bound class is read off the client, not from a table of majors. An empty database, a schema that is not pushed yet and a file written by the same major are not refused. Checked on real files written by one major and opened by another, in every direction (6, 7 and 8 against each other).
