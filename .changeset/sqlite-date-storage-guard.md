The SQLite adapters refuse a file that another Prisma major wrote. Prisma 6 stores `DateTime` as integer epoch milliseconds in SQLite, Prisma 7 and 8 as ISO text, and SQLite orders every integer before every text value, so across majors every date comparison is decided by the type: a Prisma 7 client on a Prisma 6 file offered a run completed a moment ago to `run.purge` and a run updated a moment ago to `run.reapStuck` (and the reverse never polled a stage whose deadline had passed). `PrismaWorkflowPersistence`, `PrismaJobQueue`, `PrismaStepLedger` and `PrismaAICallLogger` on SQLite now check before every method, in one statement through the client's tagged `$queryRaw`, or `$queryRawUnsafe` when that is all the client has: the oldest and newest stored value of every date column an index leads with (`workflow_runs.createdAt`, `outbox_events.publishedAt` and `dlqAt`, `workflow_stages.nextPollAt`, `job_queue.nextPollAt`), the date of one row of each table whose rows no run implies (`job_queue.createdAt`, `outbox_events.occurredAt`, `idempotency_keys.createdAt`, `ai_calls.createdAt`), and a `Date` as the client binds it, read off the client and not from a table of majors (ten index lookups and four one-row reads: p50 0.22 to 0.50 ms with 100,000 rows in each of six tables). It compares the storage class and, when both are text, the form (the text with every digit replaced, which tells Prisma 7's `+00:00` from Prisma 8's `Z`, the path of an upgrade). A foreign class or form makes the method throw the new exported `SqliteDateStorageError` (`code: "SQLITE_DATE_STORAGE_MISMATCH"`, `kind` `"class"` or `"form"`, `column`, showing what is stored and what is bound and linking the docs) before it reads or writes anything, on that call and every later one. The check fails closed: when it cannot run (a database error, a missing table) the method throws the new exported `SqliteDateStorageUnverifiedError` (`code: "SQLITE_DATE_STORAGE_UNVERIFIED"`, `reason: "probe-failed"`, the database error as `cause`) and runs nothing, and the next call checks again; a pass is remembered for the client only when it saw a stored date. On a file with no stored date the method runs and the next call checks again: every table is either sampled or holds rows that belong to a run whose date is read, so no row exists that the call could compare. **Breaking:** a SQLite client with neither `$queryRaw` nor `$queryRawUnsafe` is refused on every call with `SqliteDateStorageUnverifiedError` (`reason: "no-raw-query"`, naming both); it used to run unchecked. Which methods are guarded is decided by name (every method except a short list of synchronous ones, and loading fails if none is wrapped), not by how the code was compiled, so a build that lowers `async` still guards every entry point; a transaction's clone is checked through its parent before the transaction opens. Checked on real files written by one major and opened by another, in all six directions, for each adapter, the console read port and both hosts, with the full client, a client with only one of the two raw reads and a client with neither, cold and with a process that had started on the empty file before the other major wrote. The prerequisite: one Prisma major per file, also while it is empty. Two majors that start on an empty file cannot be told apart until one of them writes; after that, the other refuses on its next call. Not detected: a foreign text form on rows strictly between the oldest and newest of a column, and the rows of a sampled table other than the one read; only a file an earlier release mixed, or two majors writing at once, can hold them. To move a file to another major, drain it with the major that created it: `run.cancel` every run that is not terminal; `outbox.flush` until `engine.stats` reports no unpublished event; replay the dead letters (`plugin.replayDLQ`, then flush) or discard them knowingly; `run.purge` with a future `olderThan` until it purges nothing; then `DELETE FROM outbox_events;`, `DELETE FROM idempotency_keys;` and `DELETE FROM ai_calls;`, and open it with the new one: run on real files for 6 to 7, 6 to 8, 7 to 6, 7 to 8 and 8 to 7 (see the Prisma setup guide for what each step prevents). 8 to 6 does not recover: Prisma 8 declares its date columns `TEXT`, so a Prisma 6 client's writes are stored as text and unreadable; use a fresh Prisma 6 file.

New exported `assertSqliteDateStorage(prisma)` runs the same check for code that owns a client (the console read port uses it), and `JobTransport` and `JobQueue` gain an optional `verifyStorage(): Promise<void>` that a host calls at start; the Prisma job queue implements it and `createSpillingJobTransport` forwards it. Nothing is required of a custom transport.
