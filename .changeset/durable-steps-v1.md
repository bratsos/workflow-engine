"@bratsos/workflow-engine": major
---

Durable steps, injected AI services, one AI primitive with a realtime/batch policy, a builder-first typed workflow API, and the 1.0 removals.

**Breaking (major):**

- Removed the APIs deprecated for 1.0: `ModelStatsTracker`, `getModelById`, `ModelWithRecorder`, `printAvailableModels`, `getRegisteredModel`, `listRegisteredModels`, `getDefaultModel`, `modelSupportsBatch`, the positional `recordCall(modelKey, prompt, response, tokens, options)` overload (the object form stays), `requireStageOutput`, and `apiKey` on the suspended state schema. Check batch capability with `getModel(key).supportsAsyncBatch`; configure models with `registerModels()`.
- `defineWorkflow` no longer takes an `output` option. The workflow output schema is always the last stage's output schema (or the merged object of the last parallel group).
- `StageContext` and `CheckCompletionContext` gained `step`, `ai` and `aiLogger`, all **required** — `StageContext.step` is no longer optional, and `CheckCompletionContext` now carries a `step` scoped to the same stage record. Hand-built contexts (custom hosts, tests that construct a context by hand) must provide them; `createStepApi()` from `@bratsos/workflow-engine/kernel` builds a ledger-less step API that throws `StepLedgerNotConfiguredError`.
- `ctx.log` and `ctx.onLog` are typed as returning `void`. Code that awaited them still compiles; the type no longer suggests it.
- `AIStreamResult.rawResult` is `undefined` when the stream came from an adapter.
- `ModelKey` is open in both forms. The *type* accepts any string, and the exported *zod schema* is now `z.string().min(1)` instead of a registry refinement — a `schemas.config` field typed with it no longer rejects an unregistered key at `run.create` with "Model not found". Validation stays at `getModel()`.
- `WorkflowBuilder.stage(prebuilt)` and `.pipe(prebuilt)` now check the stage's declared context against the accumulated one. A stage that requires a key no earlier stage produces (or produces with an incompatible type) no longer compiles; the parameter resolves to `{ __error: "stage requires context keys not produced by earlier stages: ..." }`. Stages built without an explicit context are unaffected.
- The Prisma schema gains a `WorkflowStep` model (`attempt`, `leaseExpiresAt`, `deadlineAt` included) used by `PrismaStepLedger`; consumers using durable steps need a migration.

**New features:**

- **Durable steps.** `ctx.step.run(id, fn, { leaseMs, retries, retryDelayMs })` (`retryDelayMs` takes a duration string too), `ctx.step.waitFor(id, { poll, ready, every, timeout, pollBackoffMs })`, `ctx.step.waitForSignal(id, { timeout })` and `ctx.step.sleep(id, duration)` record side effects in a `StepLedger` (`InMemoryStepLedger`, `PrismaStepLedger`); a suspended stage resumes by replaying `execute()` with completed steps answered from the ledger. A `step.signal` kernel command completes a signal wait and is idempotent. Leases re-claim steps left `running` by a dead worker, `retries` re-run a thrown step, wait deadlines are stored once and never slide (`StepTimeoutError` on expiry), a throwing `poll` backs off instead of failing the stage, replay saves artifacts, and re-running a stage from scratch clears its ledger rows. Control-flow errors are branded (`isStepControlFlowError`) and a stage body that swallows one still suspends.
- **`ctx.step.ai`.** `generateText` and `generateObject` are memoized through the ledger. `map(id, items, spec)` runs one prompt per item under `policy: "auto" | "realtime" | "batch"` with the same schema validation and repair on both paths, an in-process concurrency limit, a call budget (`AiMapBudgetExceededError`), a stored batch deadline, and `onExpiry: "fail" | "partial"` (`AiMapBatchFailedError`). All batch bookkeeping lives in step results.
- **`ctx.ai` and `ctx.aiLogger`.** `createKernel({ services: { aiLogger, ai? } })` provides a lazily built `AIHelper` on every stage and `checkCompletion` context under the topic `workflow.<runId>.stage.<stageId>`, with call logs in the run's log table. `createMockAIHelperFactory()` in `@bratsos/workflow-engine/testing` provides the mock for tests. Accessing `ctx.ai` without services throws `AIServicesNotConfiguredError`.
- **Adapter seam.** `AIHelperOptions.adapter: AIAdapter` swaps the transport for any subset of `generateText`, `generateObject`, `embed` and `streamText` below logging and cost; child helpers inherit it. Adapter responses may carry `costUsd`, recorded as the reported cost.
- **Timeouts.** `AIHelperOptions.timeout.perCallMs` and per-call `timeoutMs` on text, object, embed and stream options; expiry throws `AICallTimeoutError` and still logs the failure row.
- **Builder-first workflows.** `defineWorkflow(id, { input }).stage(id, definition)` infers the context from earlier stages so `ctx.require()` is typed and `dependencies` only accepts earlier ids; `.stage(prebuilt)`, `.pipe()`, `.parallel([...])` and `.parallel((group) => ...)` carry the same inference; `InferWorkflowContext`, `InferWorkflowInput`, `InferWorkflowOutput`, `InferWorkflowStageIds` and `InferStageOutputById` expose the inferred types.
- The package now ships `prisma/schema.prisma`, and the Prisma adapters no longer import `@prisma/client` (Prisma 7's generator has no fixed client path).
- **Durable steps under `Promise.all`.** When one of several concurrent steps suspends, the stage factory now lets every in-flight `run` finish and record — bounded by the longest remaining lease — before the suspension is persisted, so the replay finds completed rows instead of meeting `StepInFlight` until the leases expire.
- **Step options on single AI calls.** `ctx.step.ai.generateText(id, model, prompt, options?, stepOptions?)` and `generateObject(..., schema, options?, stepOptions?)` forward a `StepRunOptions` (`retries`, `retryDelayMs`, `leaseMs`) to the underlying `step.run`, so one model call retries durably like any other step.
- **`ctx.step.ai.streamText(id, model, prompt, options?, stepOptions?)`.** Streams through `ctx.ai.streamText` on the first execution (forwarding `onChunk`) and stores the final text, tokens, cost and reasoning as one `run` step; a replay returns the stored `StepStreamResult` without contacting the model and calls `onChunk` once with the whole text. For hosts that kill an idle non-streaming connection.
- **`ctx.step.ai.map` additions.** A failed item carries `errorName` (the `Error.name` of the last failure, memoized so it survives replays; never a `cause` — results must stay JSON). `realtime.minDelayMs` paces each concurrency slot, replacing hand-written cooldowns. `stream: true` sends realtime items through `ctx.ai.streamText`, with `schema` still validating the collected text.
- **Test harness.** `createTestHarness({ workflows, services?, clock?, stepLedger?, ... })` in `@bratsos/workflow-engine/testing` returns the kernel, every in-memory port, the step ledger, the AI logger, the mock AI factory and the fake clock, plus `run(workflowId, input, config?)` (drives claim → execute → poll suspended → flush → advance until the run is terminal) and `tick()` (one round, returning a `TickReport`). `createTestKernel` is exported from the same entry.
- **Mock AI scripting.** `createMockAIHelperFactory({ helper })` hands out the caller's instance, and `createAtTopic`/`createChild` construct through `this.constructor`, so a `MockAIHelper` subclass survives. `failOnce(match, error?)` arms a one-shot failure (substring, RegExp, or a predicate over `{ modelKey, prompt, kind }`), and `mockObjectResponseForSchema(schema, value)` dispatches object responses on Zod schema identity.
- **Host helper ergonomics.** Every field of `RunMaintenanceTickOptions` and `ExecuteJobWithHeartbeatOptions` is optional, with `HOST_DEFAULTS` (which now also carries `workerId` and `logPrefix`) applied inside. `runMaintenanceTick(kernel)` and `executeJobWithHeartbeat(kernel, { jobTransport, job })` work as-is.
- **Export surface.** `WorkflowRegistry` is exported from the root entry alongside `Workflow`, and `TextInput`, `ContentPart`, `TextPart`, `MediaPart` and `StreamTextInput` are exported from both the root and `/client`, so every type in a public method signature is importable.
- Reference `skills/workflow-engine/references/12-durable-steps.md` documents all of the above and the migration from `defineAsyncBatchStage` to steps. `skills/workflow-engine/migrations/migrate-0.13-to-1.0.md` is the upgrade guide: a column-level database checklist with SQL (the `workflow_steps` table, `ai_calls.batchId`/`requestId`, and the columns every dispatch writes), the API removals with replacements, the builder and `defineAsyncBatchStage` → `ctx.step.ai.map` migrations, `createKernel({ services, stepLedger })`, the AI SDK 7 peer ranges and the behaviour changes.

**Fixes from the first real-world runs of 1.0.0-alpha.0:**

- `AIAdapter.generateObject` results were read from `output` instead of `object`, so every adapter-based `generateObject` (and every `ctx.step.ai.map` item with a schema) returned `undefined`, logged an empty response and crashed. The object is resolved once from the adapter response; `generateText` reads the adapter's structured `object` the same way. The adapter seam is now covered end to end through the kernel (a real `createAIHelper` over a fake adapter across `generateText`, `generateObject`, `streamText`, `map` realtime and `map` with repair).
- `ctx.step.ai.map` repair now engages for any error that carries the model's raw text (`text` or `cause.text`), a `ZodError` or a JSON `SyntaxError`, not only the AI SDK's `AI_NoObjectGeneratedError`; `NoObjectGeneratedError` is re-exported from the root entry so adapters can throw it. Realtime item retries (`realtime.retries`) run **in-process** — wait `retryDelayMs`, bump the ledger row's `attempt`, call again — instead of suspending and replaying the whole stage. `ctx.step.run` retries still suspend the stage.
- The step seq ordinal is stable across replays of a stage that runs a map: item seqs are reserved in item order before any ledger lookup resolves, so a slow ledger cannot permute them and a `step.run` after the map is no longer reported as "non-deterministic step order".
- `NodeHost.stop()` waits (bounded by `shutdownTimeoutMs`, default 10s) for the job in flight and then runs a final `outbox.flush`, so `workflow:completed` for a run finished by that process is published before it exits instead of by whichever process ticks next; `flushOutboxOnStop: false` opts out. The serverless host, which has no lifecycle, flushes after each `handleJob` (`flushOutboxAfterJob`, default true, bounded by `outboxFlushTimeoutMs`). The remote package is an activity worker with no outbox and is unchanged.
- A stage failure with job attempts left is no longer recorded as `FAILED`: `job.execute` takes the job's `attempt`/`maxAttempts` (both hosts and the test harness pass them), leaves the stage `PENDING` with the error on `errorMessage`, keeps its ledger rows, and returns `willRetry: true`; the host re-enqueues through `jobTransport.fail(jobId, error, true)`, whose contract now states the transport must re-queue with backoff. With no attempts left the stage is `FAILED` and `run.transition` runs immediately on every host — previously a serverless consumer whose transport acknowledged without re-enqueueing saw a `FAILED` stage under a `RUNNING` run until `run.reapStuck`. The `maxRetries` field of the config presets is not read by the kernel; the transport's `maxAttempts` is the retry budget.
