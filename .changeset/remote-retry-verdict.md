A stage that throws on a remote worker is classified the way a local one is. The worker reports the error's `name`, also for a thrown value that is not an `Error`. When the kernel's `isRetryableStageError` rejects the error (a `NonRetryableError`, a Zod error from any copy of zod, a duplicate step key), it also reports `retryable: false` on the failed outcome. The `RemoteExecutor` passes both to `job.execute`, so the job is not retried and the stage records the same `"Name: message"` text a local stage would. A stage input that fails validation in the `RemoteExecutor` is non-retryable too, as in `LocalExecutor`. Both fields are optional: a worker that sends neither behaves as before, and a broker that does not know them drops them. A `defineRemoteStage` proxy fails the run on a failed outcome, retryable or not. A failed outcome with an empty message, such as a worker throwing `new NonRetryableError()`, now fails the run under the error's name; it used to leave the stage suspended.
