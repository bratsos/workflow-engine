`NodeHost` gains `wake(): void`, which makes the host look for work now instead of at its next timer. It ends the job loop's idle wait (`jobPollIntervalMs`) and runs an orchestration tick at once, and when that tick ends the job loop looks for work again, so a run created between ticks has its first stage dequeued within about a second instead of after up to `orchestrationIntervalMs` plus `jobPollIntervalMs`. Calls coalesce: a call that arrives while a tick or a job pass is running is remembered, and exactly one more pass of that kind follows however many calls came, so two passes of a kind never run at once. `wake()` does nothing before `start()` and after `stop()`, and the timers remain the fallback; a job loop that is pausing after a completed job (`postJobYieldMs`) or backing off after an error finishes that pause first. The tick a wake runs is the whole tick and claims at most `maxClaimsPerTick` runs. The engine adds no dependency and opens no `LISTEN` connection: wire your own `pg` or Bun `sql.listen` listener on the `workflow_engine_runs` channel to `host.wake()` (examples in the Node host docs and the package README). `stop()` also ends the job loop's idle wait now, so it no longer waits out `jobPollIntervalMs` for a loop that is parked on an empty queue. Rollout: rolling-safe; the host reads and writes nothing new, so hosts of different versions can run together.
