A dead-lettered outbox event can no longer be lost to a crash. `outbox.flush` stamps `publishedAt` when it claims an event and, on the last allowed failure, moved the event to the DLQ and then released the claim in a second write. A process that died between the two left `dlqAt` and `publishedAt` both set, and `plugin.replayDLQ` cleared only `dlqAt`: the event then read as published and was never delivered (reproduced through `outbox.flush`, an injected crash, `plugin.replayDLQ` and `outbox.flush` on Prisma 7 SQLite: the replay reported 1 event and the next flush published 0). `moveOutboxEventToDLQ` now sets `dlqAt` and clears `publishedAt` in one write, and `replayDLQEvents` clears any `publishedAt`, in the Prisma adapters (Prisma 6, 7 and 8, PostgreSQL and SQLite) and the in-memory adapter. Rows an earlier version left in that state count as dead-lettered in `engine.stats` and are revived by the next `plugin.replayDLQ`; `UPDATE outbox_events SET "publishedAt" = NULL WHERE "dlqAt" IS NOT NULL AND "publishedAt" IS NOT NULL` normalises them without a replay. A custom `Persistence` must clear the stamp in the same write in `moveOutboxEventToDLQ` and in `replayDLQEvents`; `persistenceConformanceSuite` checks it.
