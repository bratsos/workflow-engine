SQLite writes queued through the Prisma adapters during an active transaction now wait for it and then run, whether it commits or rolls back. Only a write proven by async context to come from inside a transaction that rolled back is rejected with `P2028`, so another writer's rollback no longer rejects or discards unrelated work, including on Prisma 7, where a root statement shares the transaction's connection. A write whose callback lost its async context through an external `AsyncResource` runs after the rollback and persists: use the passed transaction client for transactional writes. Native SQLite adapters serialize root writes and both transaction forms before Prisma starts them, keeping driver acquisition waits outside the connection pool, and transactions opened on the same client take a turn in that queue. Batched enqueues retain batch semantics without gaining an interactive timeout. Expired native transaction callbacks release the queue even when the callback never settles, and the rejection now says the timeout passed.
